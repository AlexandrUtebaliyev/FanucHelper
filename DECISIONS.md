# DECISIONS — вопрос → что выбрал → почему

1. **`node --test tests\` на Node 24 не принимает каталог** → добавлен `tests\index.js`, который подключает все `*.test.js` → команда из ТЗ работает без изменений.
2. **Шрифты Inter / JetBrains Mono** (в макетах подключаются из сети) → в приложении системные шрифты-запасные → ТЗ требует полностью офлайн, а из сети разрешён только `npx serve`.
3. **Модули ES (`type: module`)** → `package.json` без зависимостей только для типа модулей → иначе тесты на `node --test` не импортируют ESM.
4. **Система G-кодов B/C** → генератор циклов отказывается выводить код и показывает сообщение → таблица кодов B/C — справочные данные, по памяти не вношу (см. TODO_DATA.md); безопасней не выводить, чем вывести неверный цикл.
5. **Дуга G02/G03** → «против часовой» в плоскости (Z вправо, X вверх) = G03 для заднего держателя, зеркально для переднего → совпадает с макетом (G03 для R0.5 на уступе) и ТЗ.
6. **Фаска «длина × угол»** → длина откладывается по оси Z, угол — к оси, катет по радиусу = длина·tg(угол) → в ТЗ не уточнено; так принято в чертежах (2×45°).
7. **Диаметр под наружную резьбу** → показывается рекомендация D − 0.1·P с подписью «рекомендация» → ТЗ требует «диаметр под резьбу», но без формулы; значение подписано как рекомендация, а не как данные стандарта.
8. **Подвод G76/G92 по Z** → начало цикла по Z = Z0 + max(3·ход, 3 мм), по X — D+2 (наружная) / Ø отверстия−2 (внутренняя) → запас на разгон шпинделя и безопасный подвод.
9. **Многозаходная резьба** → отдельный вызов цикла на каждый заход, старт сдвинут по Z на шаг, F = шаг × заходы, показано предупреждение → G76 не имеет безопасной сквозной поддержки заходов; расчёт требует проверки на станке.
10. **Угол профиля G76** → допустимы только 0, 29, 30, 55, 60, 80 → иначе ошибка, вывод кода блокируется.
11. **G76: «R0.»** → во втором блоке явно выводится R0. (конусность нет) → явное значение безопаснее умолчания.
12. **Первый блок контура G71 после G00 X.. Z2.** → см. этап 2.
13. **Точка подвода G71: `X(заготовка + 2e)` (ТЗ) или X44 (макет)** → `X = Ø + 2·max(e, 1)` → при e=0.5 даёт X44 как в макете, при больших e — не меньше, чем по ТЗ; запас по X всегда безопаснее.
14. **G70 с F или без** → F выводится и в G70, и в первом G01 контура → ТЗ показывает `G70 P Q F`, макет — F внутри контура; оба варианта дают одинаковый результат.
15. **Нумерация перемещений в проверке траектории** → с нуля, нулевое — подвод `G00 X44. Z2.`; 9 перемещений, 6-е (индекс 6) — G03 → так в макете («6 / 9», точки 0…8).
16. **Первая точка контура с «C1»** → фаска строится от воображаемой линии торца (вход вверх по торцу) → в макете фаска стоит на первой точке, без неё первый блок был бы с Z.
17. **G72** → контур разворачивается (от патрона к центру), первый блок — только Z → так требует цикл; монотонность проверяется для развёрнутого профиля.
18. **Профиль не монотонный (карман)** → G71/G72 не выводятся, показывается красная плашка с предложением G73 → безопаснее молчаливого кода с подрезом.
19. **G73** → припуск Δi = перепад Ø/2 + припуск, число проходов R = Δi/Δd — ориентировочные значения с предупреждением.
20. **Направление вершины T5–T8** → не реализовано (нет надёжных данных), выбор блокируется сообщением → см. TODO_DATA.md.
21. **Компенсация одной прямой (конус)** → контур достраивается цилиндрами по 5 мм до и после конуса → у отдельной прямой смещение концов не определено без соседних участков.
22. **G90/G92/G94 (TF, система A) и G76 при разборе** → цикл рисуется приближённо одним перемещением (флаг `approx`), позиция после цикла — стартовая → полная имитация цикла не требуется для проверки подвода.
23. **Граница патрона** → в настройках по умолчанию не задана; проверка выдаёт жёлтую плашку «не задана» → любое число по умолчанию дало бы ложную уверенность.
24. **Ø заготовки при проверке G00, если не задан** → берётся X последнего G00 перед первым G71/G72 (оценка сверху) → так сказано в п. 11.3.
25. **G99/G98 в цикле сверления** → первый кадр `G99 G81 …`, средние — только `X Y` (G99 модален), последний — `G98 X Y`; для одного отверстия сразу G98 → по ТЗ п. 8.2; последний кадр с G98 безопасен.
26. **Перед циклом выводится `G00 G90 Z<исходная плоскость>`, затем `G00 X Y`** → ТЗ этого не требует; без явного подъёма XY-перемещение могло бы идти на неизвестной высоте.
27. **Исходная плоскость < плоскости R или R ≤ 0** → вывод кода блокируется с сообщением → цикл «вернулся бы» в плоскость R / сверлил бы с уровня ниже поверхности.
28. **Полярные координаты G16** → центр задаётся через `G52 X Y`, отмена `G15` и `G52 X0. Y0.` → в G90 начало полярной системы — нуль (локальной) системы координат; нужна проверка на станке, поэтому в интерфейсе стоит предупреждение.
29. **Вызов G65 P9010** → только для G81, остальные циклы блокируются → текст макроса O9010 сверлит только G81.
30. **G84** → `M29 S…` перед циклом, `F = S × шаг` при G94, `F = шаг` при G95 (с возвратом `G94` после `G80`) → по ТЗ 8.1/8.2.
31. **Тексты макросов O9010–O9012** → написаны мной (Custom Macro B) без проверки на стойке; в интерфейсе — предупреждение «прогнать в графике и на воздухе»; текущая позиция Z берётся из `#5043` → не проверено на станке.
32. **Торцовка** → X от −Ø/2−вылет до L+Ø/2+вылет, подвод по Z вне материала, в зигзаге шаг по Y делается на кромке вне заготовки → безопасный врез вне детали; начало координат — угол детали X0 Y0.
33. **Сопряжения дуга–дуга и прямая–дуга** → показываются все варианты, номер варианта и направление G02/G03 выбирает оператор, предупреждение на экране → решение неоднозначно, молча выбирать нельзя.
34. **G52 в проверке траектории** → не моделируется (нужен для G16) → центр смещения не влияет на проверку R/G98/G80.
35. **Таблица ISO 286** → в `iso286.js` лежат только интервалы размеров, значения IT и отклонений из тестов ТЗ (IT7 для 6–10 и 18–30, IT6 для 30–50, g для 30–50); h, H, js вычисляются по определению стандарта → для всего остального выводится «нет данных для этого размера».
36. **Граница интервала** → «свыше a до b включительно»; 3, 6, 10, 18, 30, … относятся к нижнему интервалу → по ТЗ (18 → 10–18).
37. **G10 для коррекций инструмента** → без введённого вручную кода L ничего не выводится; слова (`R` для MF, `X Z` для TF) — шаблон, в интерфейсе плашка «БЕТА» → формат L и слов должен подтвердить наладчик по руководству 0i-F.
38. **Привязка: знак кромки** → «касание со стороны −» даёт кромку = касание + D/2, «со стороны +» — касание − D/2 → в ТЗ «знак зависит от стороны касания»; задано явно переключателем.
39. **Резьбофреза, глубина не кратна шагу** → число витков = целое, резьба нарезается на кратную шагу глубину, показывается предупреждение → шаг винтовой линии не меняется, последний Z показан.
40. **Резьбофреза, наружная резьба** → фреза идёт по радиусу (D + d)/2, подача центра F·(D+d)/D → по ТЗ; проверка «проходит в отверстие» только для внутренней.
41. **Подпрограмма резьбофрезы** → показывается отдельным блоком и не попадает в «В программу» → подпрограмму нельзя вставлять в тело основной программы.
42. **Библиотека: изменение текста сбрасывает «Проверено на станке»** → при сохранении новой версии статус возвращается в «Черновик» → проверка относилась к старому тексту.
43. **Автопроверка и «Проверено на станке»** → автоматически статус выше «Ошибки в проверке» не ставится никогда (`setStatus(..., manual=false)`) → ТЗ: только вручную.
44. **Шапка MF: `G43 Z.. H..` → `G00 G43 Z.. H..`** → без активного G00 после смены программы модальный G01 мог остаться от предыдущей программы; быстрый ход к безопасному Z безопаснее.
45. **`G28 U0. W0.` с десятичной точкой** (в ТЗ `U0 W0`) → общее правило ТЗ «точка обязательна»; значение то же.

47. **Блок из другого профиля** → программа не собирается с сообщением → в TF-программе не должно быть кадров MF и наоборот.

49. **G75: привязка по кромке** → привязка слева: стартовый Z = правый край канавки − ширина пластины, конец = левый край; справа: старт = правый край, конец = левый край + ширина → кромка пластины опорная; Δk строго меньше ширины пластины (иначе гребни).
